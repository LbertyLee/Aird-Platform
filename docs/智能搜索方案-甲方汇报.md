# 智能搜索建设方案

## 一、建设目标

建设面向业务人员的一站式智能研究与数据搜索能力。用户以自然语言描述问题，系统理解查询意图，按需检索内部知识、结构化数据和公开网络信息，对候选证据进行相关性与覆盖度校验，最终提供带来源依据的中文答案，并支持进一步的数据提取、分析和报告生成。

本方案的核心目标是提升“找得到、答得准、可核验、可继续分析”的业务体验，不把大模型生成文本本身作为正确性保障。

## 二、用户使用方式

用户输入问题后，可根据资料范围选择检索方式：

| 方式 | 适用场景 | 检索范围 |
| --- | --- | --- |
| 知识库搜索 | 查询企业内部资料、上传文件和已沉淀知识 | 内部授权知识库 |
| 联网搜索 | 查询最新公开信息、外部网站和公开数据 | 互联网公开来源 |
| 混合搜索 | 同时需要内部背景和外部信息交叉补充 | 内部知识库与外部来源 |
| AI 搜索 | 使用 AI 搜索服务发现和获取公开网页信息 | 独立的外部 AI 搜索通道 |

检索完成后，用户可查看答案、来源和证据摘要；对于可识别的结构化数据，可继续选择来源生成分析表、图表和可视化报告。不同问题和数据形态的可分析程度会有差异，纯文本来源不保证都能直接形成数值图表。

## 三、总体方案

```text
用户自然语言问题
        ↓
意图理解与需求拆解
        ↓
按模式路由：知识库 / 结构化数据 / 联网搜索 / 混合搜索 / AI 搜索
        ↓
多轮检索与证据评估 ── 信息缺口 → 定向补查
        ↓
来源去重、相关性筛选、证据归集
        ↓
基于证据生成中文答案并保存检索记录
        ↓
用户按需进入数据提取、标准化、图表和报告
```

### 1. 意图理解与任务拆解

系统分析用户问题中的主题、指标、地区或主体、时间范围、单位、币种和统计口径，将复杂问题拆成可逐项核验的子目标。对中文问题，可为外文站点生成英文检索表达；明确指定来源时，后续查询遵守来源范围。

### 2. 多源检索与路由

系统依据用户选择和问题特征进入相应检索路径：

- 内部知识库通过语义检索召回相关文档内容。
- 结构化问题可通过语义目录和 Text-to-SQL 查询已接入的数据。
- 外部搜索由搜索规划选择相关网站并获取候选结果。
- 混合模式并行获取内部和外部结果，再进行合并整理。
- 对已接入的官方结构化数据，可优先通过官方 API 获取可核验数据。

### 3. 证据评估与有限补查

候选证据会按问题相关性筛选，并检查其对指标、主体、年份、单位、币种、统计口径及来源可信度的覆盖情况。发现缺口时，系统围绕未覆盖部分继续查询，避免反复执行相同查询；达到轮数上限、没有新查询或已有证据足以回答时结束。

### 4. 答案与来源呈现

最终回答以已获取证据为基础，保留来源链接及必要的原始单位、年份和口径。证据无法覆盖的内容应明确说明缺失，不应将模型推测包装成已核实事实。检索任务和结果保留为历史记录，便于用户回看。

### 5. 后续数据分析

用户选择需要分析的来源后，系统按需补全网页正文，识别指标和观测值，对数据进行标准化并形成分析工作台。支持能力取决于来源是否包含可解析的结构化数据、指标映射是否齐备以及数据覆盖是否完整；抽取结果不完整时应提示缺失，不以空值补造数据。

## 四、技术与运行保障

- **异步执行：** 搜索通过任务队列在后台运行，前端使用 SSE 接收阶段进度，并以 HTTP 查询作为断线兜底，降低长时间搜索对页面连接的依赖。
- **访问控制：** 搜索接口要求登录并执行用户权限校验；任务状态按用户隔离。知识库来源继续经过已有访问权限检查。
- **数据留存：** 搜索记录、来源和结构化内容按现有数据链路保存；公开官方数据及可复用的结构化结果可通过缓存减少重复获取和处理。
- **服务配置：** 外部搜索服务需要部署侧配置对应的服务密钥。密钥仅保留在服务端，不传至浏览器；未配置或上游不可用时，应给出明确错误，不静默切换到另一数据来源。
- **可运维性：** 生产异步队列依赖共享 Redis 和相应持久化配置。进程中断后的任务可能从入口重跑；当前不应承诺从中断节点续跑或全链路恰好一次执行。

## 五、现有能力与实施边界

根据当前仓库的实现说明，现有搜索已具备多检索模式、LangGraph 规划与有限轮补查、证据筛选、官方世界银行结构化数据适配、来源记录、异步任务与进度推送，以及按需的数据抽取和可视化分析链路。

向甲方汇报时建议同时说明以下边界：

1. 外部搜索质量受第三方搜索服务、网站可访问性和公开资料质量影响；服务可用性与调用成本需结合采购及部署配置确认。
2. 当前世界银行适配器覆盖的是已支持的国家级指标，不代表所有国家、地区和指标均已接入官方 API。
3. 自由文本网页的数值抽取受正文质量和表格结构影响；复杂表格、扫描件、缺少单位或口径的数据需要人工复核。
4. “证据充分”是系统按规则和模型评估的结果，重要业务决策仍建议核对原始来源；不应对未覆盖的数据作确定性承诺。
5. 搜索异步能力依赖生产 Redis、反向代理对 SSE 的正确配置及部署验收。任务刷新恢复、取消、完整断点续跑和跨月计费幂等不属于当前明确具备的能力。

## 六、建议实施与验收

### 阶段一：业务范围确认

与甲方确认重点业务问题、可用知识库范围、公开来源白名单、重点指标与口径、用户权限边界、数据保留要求和外部服务采购方式，形成可验收的问题集。

### 阶段二：配置与联调

完成生产密钥和 Redis 配置、搜索来源配置、反向代理 SSE 设置以及前后端版本联调。验证不同检索模式、权限隔离、任务进度、断线查询兜底及第三方服务异常提示。

### 阶段三：试运行与效果评估

选择覆盖内部资料、最新公开信息、结构化指标和复杂多条件问题的代表性问题进行试运行。记录检索成功率、来源可核验率、关键字段覆盖率、答案人工复核通过率、平均耗时、失败率及单次调用成本，再根据结果调整目录、来源和预算。

### 建议验收口径

| 验收项 | 验收方式 |
| --- | --- |
| 模式正确 | 逐项验证知识库、联网、混合及已配置 AI 搜索路径 |
| 来源可追溯 | 抽查答案与来源链接、摘要或结构化记录之间的一致性 |
| 缺口有提示 | 准备缺失年份、地区或指标的问题，检查结果能否披露未覆盖项 |
| 权限隔离 | 使用不同账号验证知识库访问与搜索任务查询边界 |
| 异步可用 | 检查阶段推送、SSE 中断后的查询兜底和任务终态 |
| 数据分析可复核 | 抽查单位、年份、统计口径、数据来源和不完整状态 |
| 运行成本可观测 | 记录外部搜索、网页抓取及模型调用量和费用 |

## 七、汇报结论

智能搜索不是单次关键词查询，而是一条从自然语言理解、多源检索、证据校验、缺口补查到结果分析的完整业务链路。现有平台已具备这条链路的主要技术能力；项目落地重点是确认甲方的数据与权限范围、配置生产服务、用代表性业务问题进行效果验收，并以来源可核验率、数据覆盖率、响应稳定性和调用成本作为持续优化依据。
