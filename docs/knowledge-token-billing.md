# 文档学习 Token 计费

用户上传知识文件后，学习任务采集供应商响应中的真实 Token 用量，不使用固定扣分、文件大小或字符数估算。纯文件存储、等待公开审核、未调用模型的本地解析不产生 Token 费用。

## 费用公式与配置

每次执行的费用为各模型 `输入 Token × 输入元/百万 Token + 输出 Token × 输出元/百万 Token` 之和除以一百万，再除以管理端积分规则的 `yuanPerPoint`，最后向上取整。各批次先合计再取整。向量模型只有输入 Token，输出 Token 记为零。

在管理端积分规则中配置 `EMBEDDING_MODEL` 对应的模型单价，也可配置 `default` 单价；未设置数据库模型价格时沿用 `LLM_MODEL_PRICING_JSON`。不再使用 `KNOWLEDGE_LEARN_COST_POINTS`。

支持 OpenAI 兼容响应的 `usage.prompt_tokens`（回退 `total_tokens`）及 DashScope 多模态响应的 `usage.total_tokens`（回退 `input_tokens`）。当前向量请求仅发送文本，总用量按该模型配置的输入单价计算；如果将来支持图片或视频，需扩展分类用量和单价，才能按不同模态分别计费。计费作用域内缺失有效 usage 会中止学习并显示错误，禁止用字符数补算或悄悄按零消费成功。

## 执行与重试

- 用户上传来源的付款人为条目的 `submittedBy`，后台审核操作人不会替换付款人；管理来源的数据不向用户收费。
- 开始学习需有可用积分，余额不足一积分时拦截。这是准入条件，实际扣费仍按 Token 计算。
- 各次执行的实际用量先写入 `ingestion_jobs.billing_state`，再结算积分，最后启用新知识版本。积分流水包含输入、输出 Token 数。
- 同一结算引用在数据库账户行锁和唯一键下仅扣一次。待结算状态随任务保存，重试时先结算，已经完成的学习不重新调用模型。
- 自动重试确实重新请求供应商时，会产生新的 Token 费用。后续索引失败不抹除已经产生的实际 Token 消耗；失败前未调用模型则扣零分。
- 余额不足以结算或单价缺失时任务失败并保留待结算记录。补足积分或配置价格后，通过接入任务重试接口恢复原任务结算。
- 月度消费统计包括学习和智搜，使用全量月度流水聚合，避免仅统计最近二十条造成漏计。

## 上线与验证边界

先运行迁移 `20261116070000_add_ingestion_billing_state`，再生成 Prisma 客户端、发布 API，确保 Redis 学习队列、向量供应商及 Milvus 可用。未配置学习队列时明确失败，不再静默跳过任务。

自动测试使用供应商响应模拟，覆盖真实 usage 采集、不同 Token 对应不同积分、聚合取整、幂等扣费、余额不足、失败结算和结算重试。仍需在实际环境完成一次上传，核对供应商 usage、任务记录、积分流水与余额变化。
