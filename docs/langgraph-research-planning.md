# LangGraph 规划-执行循环

外部研究检索采用 Planner -> Searcher -> Evaluator -> Planner 的有界循环，最终答案由 Writer（`DeepSeekChatService.answerFromEvidence`）生成。

## 流程

1. Planner 先理解用户意图，把问题拆成数据需求，结合语义目录选择最多 5 个合适的网站，并为每个网站生成查询词。
2. Searcher 只请求本轮计划的网站。国外网站使用英文查询，国内网站使用中文查询。用户指定来源时始终限制在指定来源内。
3. Evaluator 逐项检查指标、实体、年份、单位、币种、统计口径和来源可信度，判断证据是否足以回答全部数据需求。
4. 不充分时，Planner 接收 `gaps`，只生成未覆盖子目标的新查询；已执行的网站和查询不会重复执行。
5. 达到充分性、没有新的查询、规划/评估不可用或达到 `RESEARCH_MAX_ROUNDS`（默认 3，最大 5）后结束循环。已有证据会保留，部分失败不会丢弃成功结果。
6. Writer 使用实际证据生成简体中文回答。英文指标首次出现时给出中文名称，并保留原始年份、币种、单位和统计口径；没有证据的子目标必须明确说明，不补造数值。

## 代码位置

- `apps/api/src/modules/search/research-planning-graph.service.ts`：首轮意图和来源规划。
- `apps/api/src/modules/search/research-retrieval-graph.ts`：Planner-Searcher-Evaluator 循环状态机。
- `apps/api/src/modules/ai-query/ai-query.service.ts`：调用循环、保存证据和研究循环元数据。
- `apps/api/src/infrastructure/ai/deepseek-chat.service.ts`：来源规划、证据充分性评估和中文 Writer。

规划中的动态指标、实体和网站是请求级信息，不会伪造后台指标 ID，也不会自动写入目录。后续数据分析抽取仍以已配置指标目录为准；新指标可以完成意图识别和外部证据检索，但要进入结构化图表需要补充对应的字段映射。

## 外部网站与中英文转换

模型推荐的网站会经过公开 DNS、协议、凭据、内网地址和域名校验。目录没有合适来源时，且用户没有指定来源，系统才允许有限的公开网页发现；不会恢复为扫描全部配置网站。`translations` 和中英文 discovery query 只用于语义匹配和检索，不把不相关的泛化词加入问题。

## 官方结构化数据与覆盖缺口

国家识别通过共享中英文别名表补充后台目录，包含中国、美国、法国、英国、俄罗斯等常用国家，支持 `Russian Federation`、`Russia`、`RUS` 等别名。共享表不是完整的全球国家库，其他国家仍依赖目录和模型识别。分析时合并原问题中的国家，避免旧检索计划漏掉法国、俄罗斯；俄罗斯官方英文名称在图表中显示为“俄罗斯”。

对于世界银行适配器支持的国家级指标（GDP 总量、人均 GDP、GDP 增长、人口、失业率等），Searcher 先请求固定的世界银行官方 API。用户明确限制来源且不包含世界银行时不调用该 API；城市、省份问题不会替换成国家数据。即使没有配置网页搜索密钥，适配器仍可独立获取官方数据。

`OfficialResearchCoverage` 按国家 ISO3、年份、指标代码维护实际数值覆盖，不把网页标题、摘要或模型信心当成数据。简单数值问题全部覆盖后可直接结束，不再搜索网页或调用模型评估；含解释、预测或适配器尚未支持的指标时仍需模型评估其余需求。有结构化缺口时，即使模型返回充分，也会继续补查。

缺口例如“法国（FRA）缺少 2022 年 NY.GDP.MKTP.CD 的可核验结构化数值”。下一轮官方请求缩小到尚缺数据的国家和年份，网页补查使用相应英文国名、指标代码和缺失年份。模型再规划不可用时仍可使用确定性的缺口计划。沿用默认 3 轮、最大 5 轮限制；查询重复且没有新计划时提前结束，不为尚未发布的数据无限重试或补造数值。

官方 API 行通过证据元数据保存为 `structuredData`，映射成结构化研究来源，同时保留原始 API URL、单位、世界银行指标代码与目录指标代码。进入分析表后不再抓取网页或对这些行重复调用模型抽取。分析仍以启用的后台指标目录为准。

没有覆盖的内容会作为质量说明传给中文 Writer，并保留在 `researchLoop.evaluation.gaps` 中。旧分析会话不会原地更新；发布后需要重新检索并创建分析，才能使用新的完整国家计划和数据来源。本改动不改变 HTTP 建任务、SSE 进度及轮询回退接口。

## 通用名称自动翻译

`translateDisplayNames` 批量翻译英文指标、地区、机构、行业及来源标题，不限于国家字典。检索来源标题在保存时翻译，同时保存 `originalTitle`；分析中的来源、指标选项、实体筛选、明细、汇总及图表使用一致译名，`displayTranslations` 保存原名到中文的对应。数值、单位、指标代码、字段键、URL 和证据原文不参与替换。原始结构化来源也不改写。

一次最多翻译 120 个唯一名称，每批 40 个、最多 3 批并发，每批超时 8 秒且不自动重试；进程内缓存最多 1000 个成功译名。翻译必须对应原请求名称，并保留名称中的数字。失败或无法确定时保留原名，分析显示提示，不阻止数值分析。名称翻译缓存目前仅在进程内，分析结果和译名映射随会话持久化。分析流水线版本更新为 7，重新创建分析时不复用旧版本会话。

## 官方结构化数据本地持久化

世界银行适配器查询前先读取 `OfficialObservationCache`。按提供方（当前 World Bank）、国家 ISO3、官方指标代码、年份保存 JSON 文件，可跨问题、跨分析会话及服务重启复用。每份记录包含原始观测、来源 URL 和获取时间；输出观测带 `retrievedAt` 和 `cacheHit`。用户上传和私有知识库不进入这个公共缓存。

- 历史观测有效期 7 天；当年和上一年有效期 24 小时；成功响应中暂缺的数据保留 1 小时空值标记。到期后按需刷新，避免长期使用旧值。
- 只将缺失或过期国家及年份范围提交官方 API；API 为范围查询，区间中可能包含已缓存的年份，返回后只补齐当前缺口。相同完整请求在同一进程内合并，文件通过临时文件和原子替换写入。
- 请求失败不缓存为缺失值；补查失败时仍保留有效本地观测。损坏文件视为未命中；磁盘写入失败会记日志并继续使用本次数据。缓存没有命中时仍遵循 API 超时、重试及检索轮数上限。
- 默认目录为 API 工作目录下 `storage/official-data`，可通过 `OFFICIAL_DATA_CACHE_DIR` 设置绝对路径；`OFFICIAL_DATA_CACHE_ENABLED=false` 可关闭。测试默认关闭，持久化测试使用独立临时目录。
- 完整 Compose 使用命名卷 `official_data`，应用独立 Compose 使用宿主机 `storage/official-data` 绑定目录，容器重建后保留。修改缓存路径时需同步调整挂载。多实例独立磁盘不能共享数据；共享目录可复用文件，但没有跨进程请求锁。

## 其他结构化数据统一持久化

所有结构化入口还会经过 `StructuredDataStore` 和 `ResearchRepository.createSource`：用户 JSON/CSV/Excel 上传、SQL 查询结果、World Bank 之外的公开 API（如 Eurostat、UNData、自建公开 JSON/CSV）以及外部搜索结果中可解析的结构化下载，都会保留结构化原文、记录数、来源 URL、MIME 类型和元数据。研究来源、下载结果和有效的指标抽取结果均写入 PostgreSQL 的持久表；数据库无记录时会读取并回填旧磁盘文件。

- `remote` 按公开 URL 持久化结构化下载，不设置业务过期时间；只允许 HTTPS、公开域名、JSON/CSV/Excel，下载上限 2 MB。命中后不重复下载和解析。
- `extractions` 持久化有效的指标抽取结果。公开 Exa 来源按来源 URL、正文、指标目录、查询、维度提示、规划和模型配置共享，不依赖会话或用户 ID；私有来源仍按来源 ID 隔离。正文、目录或模型变化会自动生成新指纹。
- 完整分析结果写入 `analysis_sessions`，研究来源写入 PostgreSQL 原表。私有来源不会因为 URL 相同而跨用户共享；分析读取前仍必须通过原有知识库权限检查。
- 数据库记录校验摘要并按指纹唯一保存；有效数据长期保留。旧磁盘文件只作为迁移回填来源，数据库写入失败时会告警并降级，不让来源数据错误导致当前分析请求失败。

需要先部署 `structured_data_records` 数据库迁移。旧目录默认是 API 工作目录下 `storage/structured-data`，可通过 `STRUCTURED_DATA_CACHE_DIR` 指定；仅用于迁移既有记录和数据库故障降级。`STRUCTURED_DATA_CACHE_ENABLED=false` 可关闭该持久层。World Bank 的按单元格缓存仍保留，因为它能精确补齐缺失国家/年份；新持久表负责共享复用其他结构化来源和抽取结果。

命中缓存可减少下载、解析和重复抽取成本，但规划、评估、名称翻译和最终总结仍可能调用模型，不能保证整次查询零费用。
